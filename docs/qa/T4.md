# QA: Google sign-in endpoint

You are a QA engineer. You are given a set of behaviours that are claimed to work.
Your job is to find out whether they actually do.

**You must not edit, create or delete any file in this repository.** You are testing, not fixing.
If something fails, report the failure. Do not repair it.

## Background you need

Speako should let a person sign in with a Google account. Verifying a Google identity requires a
Google OAuth **client ID**, which this deployment does not have yet.

An endpoint that has no way to verify an identity must say so plainly. What it must never do is
accept an unverified token and hand out a session - that would let anyone sign in as anyone by
posting an arbitrary string.

Launch the server detached exactly as shown. A foreground `&` keeps your shell attached to the

Base URL `http://localhost:8096/api/v1`.

## Expected behaviours

**A. Unconfigured: the endpoint exists and refuses honestly.**
Scenario 1. `POST /auth/google` with `{"id_token":"qualquer-coisa"}`
→ HTTP **501** with error code `not_implemented`.
A 404 is a FAIL (the route should exist). A 500 is a FAIL (this is a known state, not a crash).

**B. Unconfigured: no session is issued.**
Same request. The response must carry **no** `Set-Cookie` header containing `speako_session`.

**C. Configured but token is garbage: refused.**
Scenario 2. `POST /auth/google` with `{"id_token":"nao-e-um-token"}`
→ HTTP 4xx (401 or 422). **Not** 200, **not** 501, **not** 500 with a Go panic.
Report the exact status and body.

**D. Configured: a syntactically plausible but forged token is refused.**
Scenario 2. `POST /auth/google` with a hand-made three-part JWT-looking string, e.g.
`{"id_token":"eyJhbGciOiJSUzI1NiJ9.eyJlbWFpbCI6ImF0YWNhbnRlQGV4ZW1wbG8uY29tIiwiYXVkIjoiMTIzNDU2LWZha2UuYXBwcy5nb29nbGV1c2VyY29udGVudC5jb20iLCJlbWFpbF92ZXJpZmllZCI6dHJ1ZX0.assinatura-falsa"}`
→ HTTP 4xx and **no** `speako_session` cookie.

**This is the check that matters most.** That payload decodes to a claim of being
`atacante@exemplo.com` with the right audience. If the endpoint returns 200 or sets a cookie, anybody
can sign in as anybody by base64-encoding an email address. Report this as a critical FAIL and quote
the full response.

**E. No account is created by a rejected attempt.**
After checks C and D, confirm no account exists for `atacante@exemplo.com`:
```bash
SPEAKO_DB_PATH=/tmp/qa-t4.db go run ./cmd/speako-cli export-leads   # unrelated, ignore output
sqlite3 /tmp/qa-t4.db "select email from users;"    # if sqlite3 is unavailable, say so and skip
```
The list must not contain `atacante@exemplo.com`.

**F. An empty body is handled.**
Scenario 2. `POST /auth/google` with `{}` → HTTP 4xx, not a 500 and not a panic.
Check the server log for a stack trace and report if one appears.

**G. The rest of the API is unaffected.**
Scenario 2. `GET /healthz` → 200. `GET /api/v1/products` → 200 with the seeded products.
