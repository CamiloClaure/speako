# QA: Speako operator CLI

You are a QA engineer. You are given a set of behaviours that are claimed to work.
Your job is to find out whether they actually do.

**You must not edit, create or delete any file in this repository.** You are testing, not fixing.
If something fails, report the failure. Do not repair it.

## Background you need

Speako is run by one teacher with shell access to the server. The command-line tool
`speako-cli` exists for operations that do not justify a screen. Two of its jobs matter here:

- handing a person a working sign-in link when no email provider is configured;
- giving an account a password so it can sign in normally.

## Setup

```bash
export PATH=/home/camilo/.local/go/bin:$PATH
cd /home/camilo/personal/speako/api
export SPEAKO_DB_PATH=/tmp/qa-t3.db
rm -f /tmp/qa-t3.db /tmp/qa-t3.db-wal /tmp/qa-t3.db-shm
go run ./cmd/speako-cli migrate
go run ./cmd/speako-cli seed
```

The seed creates a teacher account: `professora@speako.com.br`.

For the checks that need a running API:
```bash
go build -o /tmp/qa-t3-api ./cmd/api
setsid nohup env SPEAKO_ADDR=:8097 SPEAKO_DB_PATH=/tmp/qa-t3.db /tmp/qa-t3-api > /tmp/qa-server.log 2>&1 < /dev/null & disown
sleep 2
```
Base URL `http://localhost:8097/api/v1`. Kill with `pkill -f qa-t3-api`.

## Expected behaviours

**A. The tool lists its own commands.**
`go run ./cmd/speako-cli` with no arguments prints usage that mentions **both**
a command for producing a sign-in link and a command for setting a password.
Report the exact usage text.

**B. `login-link` prints a usable URL.**
Run the sign-in-link command for `professora@speako.com.br`.
→ prints a URL to stdout containing a token. Report the exact output.

**C. The printed link actually signs that account in.**
Extract the token from the URL in check B and
`POST /auth/magic-link/verify` with `{"token":"<token>"}`
→ HTTP 200 with a `speako_session` cookie. Then `GET /me` with that cookie
→ 200 and `"email":"professora@speako.com.br"`.
A link that does not sign anyone in is a FAIL, however good it looks.

**D. The link is single use.**
`POST /auth/magic-link/verify` a second time with the same token → must NOT return 200.

**E. `set-password` lets that account sign in with a password.**
Set the password of `professora@speako.com.br` to `senha-de-teste-1`.
Then `POST /auth/login` with `{"email":"professora@speako.com.br","password":"senha-de-teste-1"}`
→ HTTP 200 with a cookie. `GET /me` with it → 200, `"role":"teacher"`.

**F. The old password stops working after a change.**
Set the same account's password to `outra-senha-2`.
Then sign in with `senha-de-teste-1` → must NOT return 200.
Then sign in with `outra-senha-2` → 200.

**G. An unknown email fails clearly on both commands.**
Run each command against `ninguem-existe@speako.com.br`.
→ each must exit **non-zero** and print a comprehensible error naming the problem.
Report the exact stderr and exit code of each.
Silently succeeding, printing a link for a nonexistent account, or a Go panic / stack trace is a FAIL.

**H. A too-short password is refused.**
Try to set a password of `abc` on the teacher account.
→ non-zero exit with a clear message; and the previous password from check F must still work.
