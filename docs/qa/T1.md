# QA: password sign-in for the Speako API

You are a QA engineer. You are given a set of behaviours that are claimed to work.
Your job is to find out whether they actually do.

**You must not edit, create or delete any file in this repository.** You are testing, not fixing.
If something fails, report the failure. Do not repair it.

## Setup

```bash
export PATH=/home/camilo/.local/go/bin:$PATH
cd /home/camilo/personal/speako/api
export SPEAKO_DB_PATH=/tmp/qa-t1.db
rm -f /tmp/qa-t1.db /tmp/qa-t1.db-wal /tmp/qa-t1.db-shm
go run ./cmd/speako-cli migrate
go run ./cmd/speako-cli seed
go build -o /tmp/qa-t1-api ./cmd/api
SPEAKO_ADDR=:8099 SPEAKO_DB_PATH=/tmp/qa-t1.db /tmp/qa-t1-api &
sleep 2
curl -s localhost:8099/healthz     # expect {"status":"ok"}
```

Base URL for every check below: `http://localhost:8099/api/v1`
All POST bodies are JSON; send `-H 'Content-Type: application/json'`.

Kill the server when you are done: `pkill -f qa-t1-api`

## Expected behaviours

Check each one independently. Record the actual HTTP status and response body for every check.

**A. Registration creates an account and signs it in.**
`POST /auth/register` with `{"email":"qa-new@speako.com.br","name":"QA","password":"senha-forte-1"}`
→ HTTP 200 or 201, and the response carries a `Set-Cookie:` header containing `speako_session`.

**B. The registered account can sign in with its password.**
`POST /auth/login` with `{"email":"qa-new@speako.com.br","password":"senha-forte-1"}`
→ HTTP 200 with a `speako_session` cookie.

**C. The session cookie actually works.**
Save the cookie from check B and call `GET /me` with it.
→ HTTP 200, and the JSON body's `email` is `qa-new@speako.com.br` and `role` is `student`.

**D. A short password is refused at registration.**
`POST /auth/register` with `{"email":"qa-short@speako.com.br","name":"QA","password":"abc"}`
→ HTTP 4xx (not 200, not 500), and no account is created: a later
`POST /auth/login` with that email and password must not return 200.

**E. A wrong password is refused.**
`POST /auth/login` with `{"email":"qa-new@speako.com.br","password":"senha-errada"}`
→ HTTP 401 with error code `invalid_credentials`.

**F. An unknown email is refused *identically* to a wrong password.**
`POST /auth/login` with `{"email":"nao-existe@speako.com.br","password":"qualquer-coisa"}`
→ HTTP 401, and the response body must be **byte-for-byte identical** to the body from check E.
Diff the two bodies and say whether they match exactly. A different message, code or field for
"no such user" versus "wrong password" is a FAIL - it tells an attacker which emails have accounts.

**G. Repeated failed logins are rate limited.**
Send 8 consecutive `POST /auth/login` requests with
`{"email":"qa-bruteforce@speako.com.br","password":"x"}` and record the status of each.
→ at least one of them returns HTTP 429. Report the exact sequence of statuses.

**H. The magic-link path still works.**
`POST /auth/magic-link` with `{"email":"qa-new@speako.com.br"}` → HTTP 202.
Then find the link: the development mailer writes it to the server's log output.
Extract the token and `POST /auth/magic-link/verify` with `{"token":"<token>"}` → HTTP 200 with a cookie.
Then POST verify **again with the same token** → must NOT return 200 (a magic link is single use).

**I. Registering an email that already exists does not silently succeed.**
`POST /auth/register` again with `{"email":"qa-new@speako.com.br","name":"QA","password":"outra-senha-1"}`
→ HTTP 4xx. Then confirm the original password from check B still signs in (HTTP 200) - the
second registration must not have overwritten the first account's password.

**J. The full existing test suite passes.**
```bash
cd /home/camilo/personal/speako/api
gofmt -l .          # expect NO output
go vet ./...        # expect no findings
go test ./...       # expect all packages ok
```
