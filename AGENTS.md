# AGENTS.md - Speako

Read this fully before writing a single line. Every rule here is enforced by a test or a reviewer.

## What Speako is

An English e-learning platform for Brazilian learners, run by **one teacher**. It sells:

- **material** - a digital file (PDF/ebook). Buying it grants a permanent *entitlement*.
- **pack** (`pacote`) - N 1:1 lesson credits with an expiry. Buying it writes entries into a *credit ledger*.

A student spends one credit to create a **booking** (`agendamento`) in one of the teacher's available
**slots** (`horários`). The video call happens **outside** Speako (Meet/Zoom); we only store the meeting URL.

Domain vocabulary is English in code, pt-BR in UI copy: `product/produto`, `pack/pacote`, `credit/crédito`,
`booking/agendamento`, `material/material`, `lead/lead`.

## The dependency rule (non-negotiable)

```
cmd/            → may import anything (composition root, wires concrete types)
internal/http/  → stdlib, internal/domain, internal/app, internal/http     ❌ NEVER internal/adapters
internal/adapters/ → stdlib, internal/domain, internal/app, third-party    ❌ NEVER internal/http
internal/app/   → stdlib, internal/domain, internal/app                    ❌ NEVER adapters, http, sql, net/http
internal/domain/ → stdlib ONLY, plus internal/domain/*                     ❌ NEVER anything else
```

Business rules must not know that Go, SQLite, HTTP, React or Mercado Pago exist. `api/arch_test.go` fails the
build if you break this. **Run `make arch` before you claim a task is done.** If the rule blocks you, the design
is wrong - stop and report, do not weaken the test.

Concretely, in `internal/domain` you may not write: `json:"..."` tags, `database/sql`, `context.Context`,
HTTP status codes, SQL strings, or any third-party import.

Interfaces (ports) are declared by the layer that **needs** them (`internal/app/ports`), never by the layer that
implements them.

## Laziness rules (ponytail)

Stop at the first option that works:

1. Does this need to exist at all? Speculative need → skip it, say so in one line.
2. Already in this repo? Reuse it. Look before you write.
3. Stdlib does it? Use it. `net/http` routes, `log/slog`, `html/template`, `crypto/*`, `time`.
4. Native platform feature? `<input type="date">` over a picker lib, CSS over JS, a DB constraint over app code.
5. Already-installed dependency? Use it. Never add a new one for what 20 lines can do.
6. One line? One line.
7. Only then: the minimum code that works.

Specifics for this repo:
- **No web framework.** `net/http` `ServeMux` with method patterns (`POST /api/v1/bookings`) is enough.
- **No ORM, no query builder.** Explicit SQL strings next to the repo method that runs them.
- **No migration framework.** Embedded `.sql` files + a small runner.
- **No mocking framework.** Hand-written fakes in `internal/app/fakes`.
- **No interface with a single implementation** unless it crosses a layer boundary (that is what ports are for).
- **No config for a value that never changes.** A constant is a constant.
- Deliberate shortcuts get a comment naming the ceiling and the upgrade path:
  `// ponytail: in-process ticker; move to a queue if we ever run more than one instance`

Deletion beats addition. Boring beats clever. If the explanation is longer than the code, delete the
explanation.

## Never be lazy about

Input validation at trust boundaries, error handling that prevents data loss, auth and payment correctness,
money arithmetic, timezone handling, accessibility basics. And never lazy about *understanding*: read the flow
end to end before choosing the smallest diff.

## Conventions

| Topic | Rule |
|---|---|
| Money | `shared.Money` - `int64` cents, BRL. Floats are banned everywhere, including tests and JSON. |
| Time | `time.Time` in UTC in code, `INTEGER` unix seconds in SQLite. Convert to a user's tz only at the edge. Use `time.LoadLocation`, never fixed offsets. |
| IDs | UUIDv7 text (sortable), generated by the `IDGen` port. Never `AUTOINCREMENT` for public IDs. |
| Errors | Wrap with `%w`. Domain errors are sentinel values (`var ErrInsufficientCredits = ...`) mapped to HTTP codes in exactly one file: `internal/http/errors.go`. |
| Context | `context.Context` is a first argument in `app` and outward. Never in `domain`. |
| Logging | `log/slog`, JSON handler, no PII in logs (no emails, no tokens, no payloads). |
| SQL | Explicit, parameterized, always. String concatenation into SQL is an automatic rejection. |
| Secrets | Only from env, parsed once into `internal/config`. Never a literal, never in a test fixture. |
| Naming | English identifiers, pt-BR only in user-facing strings. |

## Testing bar

- Every `domain` package has table-driven tests for its invariants, especially boundary values.
- Every repository has a contract test suite that runs **the same assertions** against the in-memory fake and
  real SQLite.
- Use cases are tested against fakes only - no database, no network.
- Non-trivial logic leaves one runnable check behind. No fixtures frameworks, no per-function suites.
- A test that needs the network is not a test; use a fixture.


## Session discipline

Sessions run in parallel on separate branches. **Your session owns a declared set of paths (see
`docs/sessions/SN.md`). Do not create or edit files outside it.** If you believe you must, stop and report
instead of editing - a contract change is its own session.

`docs/api.yaml` is frozen after S3. It is the single source of truth shared by both tracks; changing it
silently breaks the other track.

Commit style: `feat(booking): debit credit inside the booking transaction`. Small commits, one concern each.
